# 文字解析：搭建一个自我迭代的 Agent

> 根据视频内容整理。演讲者：Anthropic 工程师 Lamis Mukta，时长约 45 分钟。
> 核心观点：**你不应该提示 Claude，你应该构建一个能够自我迭代的 Agent**——它能记住、修复自身错误，并在每次运行中变得更强大。

## 核心主题

这篇分享主要讲的是：与其反复提示模型，不如构建能自我迭代、持续记忆和修正的 Agent。演讲围绕 **Context Engineering** 与 **Agent 长期记忆演进**展开，回答了「Agent 如何越用越聪明」的问题。

## 记忆系统的演进路径

Anthropic 内部对 Agent 记忆的探索经历了四个阶段：

1. **单文件记忆（claude.md）**——最早的尝试，把规则写在一个文件里
2. **Memory tool**——让 Agent 拥有可读写的记忆工具
3. **Skills**——把可复用的能力固化为技能
4. **Agent 可读写维护的 memory/ 目录**——Agent 自主管理自己的记忆存储

## 三条实践经验

- **格式上**：Markdown 这类「人类可读、模型也易理解」的形式非常有效
- **读取上**：渐进式加载、按需检索，比一次性全量注入更实用
- **写入上**：让 Agent 自主决定记录什么、如何组织，比硬性规则更灵活

## 生产实践：版本化与并发控制

在真实生产环境中，记忆系统还需要两个工程保障：

- **版本化**：记忆更新可追溯，任何变更都有历史
- **并发控制**：多轮、并行运行时不互相覆盖，可协作

## 效果数据

视频中给出的实践数据：

- 首次通过率错误 **减少 97%**
- 验证速度 **提升 30%**
- 团队更关注产品本身，而不是持续维护记忆基础设施

## Dreaming：离线记忆整理

后半段的重点概念是 **「Dreaming」（梦境整理）**：

- 这是一个**离线批处理过程**，目标不是执行任务，而是**整理、验证、组织记忆**
- 它拿多轮会话记录作为输入，更新成更结构化的记忆状态
- 让 Agent 第二天（下一次）运行时更聪明

整体形成「**实时记忆更新 + 离线梦境整理**」的统一记忆系统。

## 核心结论

1. 先做简单但能落地的记忆设计
2. 为多轮、长周期运行的 Agent 做系统架构
3. 用「dreaming」这类机制实现跨会话的持续学习与自我改进

## 延伸思考：落地一个「梦境整理」记忆系统

> 以下为发布者对视频观点的实践理解（非演讲者原话），供参考。

其实这正是 Anthropic 目前推荐的记忆管理方法，也已在多个主流 Agent 平台应用（如 OpenClaw），目的都是让 Agent 变得更聪明。具体实践是：在每天特定时间（闲时）启动一个预定的后台进程，读取 Agent 现有的记忆存储以及过去的会话记录，然后生成一份新的、重组后的记忆存储：

1. **合并重复项**：将重复的记忆条目整合；
2. **更新过时信息**：用最新值替换陈旧条目；
3. **浮现新洞察**：挖掘并呈现真正的新见解，让 Agent 在白天的工作中更聪明。

这套机制同样可以用来迭代我们自己的 Agent 记忆系统。需要明确的前提是：记忆系统建立在上一层主 Agent 有实时交互数据的基础之上。目前还没有现成的开源方案与框架，只能根据视频的思路自行琢磨开发。
